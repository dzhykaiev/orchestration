# E1 Scope Definition — 2026-04-01

## Objective

Introduce minimal CI protections for architecture boundaries and integration contracts after Batch 1 merges.

## In-Scope Deliverables

1. Boundary check command
- Detect forbidden imports across app/shared layers based on `docs/architecture/dependency-rules.md`.

2. Contract test scaffold
- Validate at least one queue payload and one event payload contract path.

3. CI workflow integration
- Add a dedicated, lightweight job for boundary/contracts checks.

## Not In Scope

- Full lint/test pipeline redesign.
- End-to-end environment provisioning.
- Any domain behavior changes in production code.

## Commands

- `pnpm check:boundaries`
- `pnpm test:contracts`

Status:
- `pnpm check:boundaries` implemented via `scripts/check-boundaries.sh`.
- `pnpm test:contracts` implemented as boundary + targeted contract tests:
  - `apps/api/src/contracts/planning-queue.contract.test.ts`
  - `apps/orchestrator/src/contracts/event-bus.contract.test.ts`
  - `apps/orchestrator/src/contracts/queues-runtime.contract.test.ts`
- CI gate added: `.github/workflows/contracts-gate.yml`.

## Acceptance Criteria

1. New checks fail on injected boundary violation.
2. New checks fail on intentional contract mismatch fixture.
3. CI runtime impact remains within agreed budget (target: low single-digit minutes).

## Rollout Strategy

1. Land scripts/tests behind optional CI job.
2. Observe one sprint for false positives.
3. Make job required after stability window.

Rollback toggle:
- set repository variable `ENABLE_CONTRACT_GATES=false` to skip the job without reverting code changes.

## Dependencies

- Batch 1 merged behavior from B1/C1/D1.
- Stable contract docs in `docs/contracts/**`.

## Open Assumptions

1. Repository has a canonical place for developer scripts (`scripts/`).
2. Existing test framework can host contract tests without new infra.
3. CI can run one additional lightweight job without queueing impact.
